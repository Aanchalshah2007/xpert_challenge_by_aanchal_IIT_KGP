You find OPEN LOOPS in a person's WhatsApp chats. The person is "ME". You will get several windows of messages; each window is one chat. Lines look like:
  m12 Mon 24 Aug 12:36 P7: text        (m12 = message id, P7 = sender id, ME = the person)
Lines marked * are cues worth checking, but any line can raise a loop and most marked lines are NOT loops.

A loop is a concrete thing that still needed action at the time it was raised:
- someone asks ME to do / pay / send / buy / book / decide / reply to something (owner = ME)
- someone asks ME a real question that needs an answer or decision (owner = ME)
- ME commits to doing something ("will send", "I'll check", "kar dunga") (owner = ME)
- ME asks someone else to do something and is waiting on it (owner = that person's id) -> type followup
- a dated obligation: a meeting, payment, deadline or event ME must act on (type deadline)
NOT loops: greetings, wishes, thanks, FYI, news, forwards, jokes, small talk, rhetorical questions, a request that is answered/done within the same minute, things only between other people that ME has no part in.
"No loops" is a normal and common answer for a window.

For each loop:
- src: the EARLIEST message in the window that raised this task. If a request is repeated or rephrased later, src is the FIRST one. One loop per task. If unsure, choose the concrete message.
- owner: "ME" or the sender id (P..) of the person who must act.
- type: commitment | followup | deadline | question
- title: short imperative, max 10 words.
- due: YYYY-MM-DD if a date/day is stated or clearly implied, else null. Resolve "tomorrow", weekdays etc. from the message date.
- status probabilities from the LATER messages you can see: p_open, p_done, p_dropped (sum to 1). done = later messages show it happened (paid, sent, booked, "done", answer given, meeting held). dropped = explicitly cancelled or abandoned. If you see no evidence either way, it is open.
- close: id of the message that shows done/dropped, else null.
- help features, from the point of view of an assistant that can read ME's chats and send messages for ME:
  owner_is_me, private (personal/family/health/relationship matter), reversible (a wrong step is easy to undo), sensitive (money transfer, legal, medical, confidential, emotional), needs_me_only (only the user (ME) can do it personally: their own decision, presence or payment).
  p_assist (assistant can usefully take the next step itself, e.g. draft a reply, look something up, collect details), p_remind (only ME can act; a timely reminder helps), p_leave (stay out). Sum to 1.
  next: for assist, the next step in one line, else null.
- conf: 0..1 that this is a real loop.
